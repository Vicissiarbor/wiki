# 编辑方式

四种数据源，功能一样（都是 `load / create / update / delete`），只是「改动存在哪里」不同。打开网页右上角的「设置」即可切换，**设置只保存在当前设备**。

| 数据源 | 需要什么 | 改动生效范围 | 适合 |
| --- | --- | --- | --- |
| 静态 JSON（只读，默认） | 无 | 只有你自己提交后 | 日常查询；不想在网页上误改 |
| 本地编辑 | 无 | 仅当前浏览器 | 出差/离线改稿，改完导出 JSON 提交 |
| GitHub 仓库 | 细粒度令牌 | 提交后所有设备（Pages 自动重建） | 不想开服务器，但想在网页上直接改 |
| 自建后端 | aliyun 服务器 + 令牌 | **立即**对所有设备 | 想要「像用笔记本一样」随手增删改 |

---

## 1. 静态 JSON（只读）

网页只读 `web/data/entries.json`。改词条就是在仓库里编辑这个文件（或本地改完覆盖），提交后所有设备看到新版。

- 优点：最简单、最安全、有 git 历史；
- 缺点：手机上改不了。

## 2. 本地编辑（仅此设备）

设置里切到「本地编辑」。首次加载会把站点自带的 JSON 复制一份到浏览器 `localStorage`，之后的增删改都只作用于这份副本。

- 「导出 JSON」→ 下载 `entries.json`，覆盖回仓库即可发布；
- 「导入 JSON（覆盖本地）」→ 用文件整体替换本地数据（其他数据源不支持整体导入，会提示切换到本地编辑）；
- 清空本机副本：`localStorage.removeItem('ladr.entries.local.v1')`（或者浏览器里清除站点数据）。切换回「静态 JSON」不影响仓库里的文件。

## 3. GitHub 仓库（浏览器内提交）

设置里填：

| 字段 | 例子 |
| --- | --- |
| 仓库所有者 | `your-name` |
| 仓库名 | `searchLADR` |
| 分支 | `main` |
| 文件路径 | `web/data/entries.json` |
| 个人访问令牌 | `github_pat_…` |

令牌怎么建：GitHub → Settings → Developer settings → **Fine-grained tokens** → 只选这一个仓库 → 权限只勾 **Contents: Read and write** → 有效期尽量短。

行为：

- 保存 = 用 GitHub Contents API 提交一次（提交信息形如 `content(entries): add "熵"`）；
- 需要当前文件的 `sha`，所以每次保存都基于「你加载时的版本」；如果期间别人（或你在网页另一处）改过，GitHub 会返回 409，页面提示「数据已被其他设备修改，请刷新后重试」；
- Pages 需要几十秒重建，之后所有设备都看到新内容；
- 文件必须小于 1 MB（Contents API 的限制）；词条很多时改用本地编辑或自建后端。

**令牌安全**：令牌只存在这台设备的 `localStorage`（键名 `ladr.settings.v1`），不会写入仓库。请不要把令牌写进 `web/config.json` —— 那个文件会随站点一起公开，程序检测到也会警告你。怀疑泄露时在 GitHub 上直接撤销该令牌即可。

## 4. 自建后端（多人/多设备即时生效）

设置里填后端地址（如 `http://1.2.3.4:8787`）与访问令牌（服务器上的 `LADR_TOKEN`）。详细上线步骤见 [deployment.md](deployment.md)。

- 读取是公开的（数据本来就会发布到 Pages）；
- 写入需要令牌，采用常数时间比较并带失败限流；
- 每次写入携带 `If-Match: <修订号>`，旧修订写入得到 409 而不是覆盖；
- 服务端写文件是「临时文件 + rename」的原子替换，并留一份 `.bak`；
- 加 `--git-commit --git-push` 可以让每次改动自动提交并推送回 GitHub，于是「服务器改」和「Pages 展示」自然同步。

## 冲突是怎么处理的

1. 网页加载时记下服务器返回的 `revision`（文件内容哈希）；
2. 保存时带上 `If-Match: <revision>`；
3. 服务器发现不一致 → `409`；
4. 前端 `ConflictError` → 回滚本地乐观更新 → 提示刷新；
5. 你点「刷新」拿到最新数据，再重做这次修改（只丢掉一次输入，不会丢掉别人的改动）。

## 编辑界面

- 快捷键：`n` 新增（不在输入框时）、`/` 或 `Ctrl/⌘+K` 聚焦搜索、`Esc` 关闭弹窗；
- 名称必填且唯一；别名、标签用逗号（中英文逗号、顿号都行）分隔；
- 「首字母」留空即自动判断（中文取拼音），多音字可以手动覆盖；
- 「预览」页签用与详情页完全相同的渲染器显示 Markdown，预览里写 `<script>` 也不会执行；
- 「复制 JSON」把当前表单内容复制到剪贴板，便于手工粘贴进 `entries.json`；
- 校验错误在表单内高亮，且与服务端使用同一套规则，所以不会出现「前端通过、后端拒绝」。

## 数据搬迁

| 需求 | 做法 |
| --- | --- |
| 备份全部词条 | 工具栏「导出 JSON」；或服务器上的 `.bak`；或 `git log web/data/entries.json` |
| 从别处导入 | 切到「本地编辑」→「导入 JSON（覆盖本地）」→「导出 JSON」→ 覆盖回仓库 |
| 直连后端整体导入 | `POST /api/entries/import`，见 [api.md](api.md) |
| 从别的格式迁移 | 写一个小脚本生成 `{version, updatedAt, entries:[…]}`，注意 `id` 必须唯一且为 URL 安全字符 |
