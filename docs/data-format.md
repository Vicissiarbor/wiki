# 词条数据格式

全部词条存在一个文件里：`web/data/entries.json`。它既是被发布的站点数据，也是维护内容的唯一入口（通过 git 提交更新，见 [editing.md](editing.md)）。

## 文件结构

```json
{
  "version": 1,
  "updatedAt": "2025-01-01T00:00:00.000Z",
  "entries": [
    {
      "id": "entropy",
      "name": "熵",
      "aliases": ["entropy", "信息熵"],
      "initial": "S",
      "tags": ["物理", "信息论"],
      "summary": "度量系统的不确定性或无秩序程度。",
      "content": "## 信息论定义\n\nH(X) = -Σ p(x) log₂ p(x)……",
      "createdAt": "2024-11-02T08:00:00.000Z",
      "updatedAt": "2024-12-20T15:10:00.000Z"
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `version` | 文档结构版本，当前为 `1` |
| `updatedAt` | 整份文档的更新时间（显示在页脚；可留空） |
| `entries` | 词条数组 |

> 也可以直接写一个**裸数组**（`[{…}, {…}]`）作为文件内容，加载器同样接受。

## 词条字段

| 字段 | 必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| `id` | ✅ | string | 稳定标识，决定分享链接 `#/e/entropy`。只允许字母、数字、`.`、`_`、`~`、`-`，必须以字母或数字开头，最长 128。**改名不要改 id**，否则旧链接失效 |
| `name` | ✅ | string | 词条名，**全集合内唯一**（忽略大小写）。最长 200 |
| `aliases` | ❌ | string[] | 别名，参与搜索与精确匹配。最多 50 个，每个最长 200 |
| `initial` | ❌ | string | 覆盖首字母分桶，取值 `A`–`Z` 或 `#`；留空自动判断（中文取拼音首字母） |
| `tags` | ❌ | string[] | 标签，可用 `tag:标签` 精确筛选。最多 50 个，每个最长 64 |
| `summary` | ❌ | string | 一句话简介，显示在词条页标题下方，也参与搜索。最长 500 |
| `content` | ❌ | string | 正文，Markdown 子集（见下）。最长 200000 |
| `createdAt` | ❌ | string | ISO-8601 时间，可留空 |
| `updatedAt` | ❌ | string | ISO-8601 时间，显示为词条页的「更新于」 |

未知字段会被忽略；空字符串与空数组会被跳过，所以文件可以保持干净。

## 校验规则

网页加载是**宽容**的：单条坏数据会被跳过，并在页面顶部以黄色提示报告「有 N 条词条格式不对」，不会让整页空白。
写入侧没有接口，所以"严格校验"由提交前的检查兜住：

```bash
npm test        # tests/data-files.test.js 会校验整份文件
```

会被判为不合规的情况：

- 缺 `name`，或 `name` 与其它词条重名（忽略大小写）；
- `id` 缺失、格式非法或重复；
- 别名与另一个词条的名称完全相同；
- 字段超长或数组超量；
- `initial` 不是单个 `A`–`Z`/`#`。

## 正文可用语法（Markdown 子集）

| 语法 | 效果 |
| --- | --- |
| `# 标题` … `###### 标题` | 渲染为 `h2`–`h6`（`h1` 留给词条名） |
| 空行分段，单换行 | 段落 / `<br>` |
| `- 项`、`1. 项`、缩进两级 | 无序 / 有序列表、嵌套 |
| ```` ```js … ``` ```` | 代码块（内容不参与格式化） |
| `> 引用` | 引用块 |
| `\| a \| b \|` + `\| --- \| --- \|` | 表格（`---:` 右对齐、`:--:` 居中） |
| `---` | 分隔线 |
| `` `代码` ``、`**粗体**`、`*斜体*`、`~~删除线~~` | 行内样式 |
| `[文字](https://…)`、`![图](https://…)` | 链接与图片（仅允许 `http`/`https`/`mailto`/相对地址） |
| `[[熵]]`、`[[熵\|熵与信息]]` | 跳转到另一个词条；目标不存在时显示为灰色文字 |
| 裸 URL | 自动成为链接 |

不支持（有意为之）：原始 HTML、脚注、引用式链接。原始 HTML 会被转义成文字显示——这样任何词条都无法在读者浏览器里执行脚本。

## 中文首字母是怎么来的

`web/js/core/pinyin-table.js` 是一张「码点 → 拼音首字母」的紧凑查表（覆盖 GBK 的 20892 个汉字，约 30 KB，gzip 后约 14 KB），由 `tools/gen_pinyin_table.py` 从 [pypinyin](https://github.com/mozillazg/python-pinyin) 生成：

```bash
python3 -m venv .tools/venv
./.tools/venv/bin/pip install pypinyin==0.55.0
./.tools/venv/bin/python tools/gen_pinyin_table.py
```

规则：先跳过空白、标点、符号（`《存在与时间》` → `C`），拉丁字母取首字母（`Émile` → `E`、`Ｇraph` → `G`），数字与无法识别的字符进入 `#` 桶。

**多音字限制**：逐字查表没有词语上下文，例如「重庆」会取 `重` 的默认读音 `zhòng` → `Z`。要修正就给该词条加 `"initial": "C"`。

## 手工编辑建议

- 用两个空格缩进（仓库里有 `.editorconfig`），保持 diff 干净；
- 数组里的每一项单独一行，便于 diff 与回滚；
- 每条词条后面记得加逗号、最后一条不要加——`npm test` 会替你抓住这类错误；
- 改完提交前跑一次 `npm test`，它会校验整份文件、重名、id 合法性与首字母。
