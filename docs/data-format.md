# 词条数据格式

全部词条存在一个文件里：`web/data/entries.json`。它同时是**站点数据**、**后端数据文件**和**导入导出格式**。

## 文件结构

```json
{
  "version": 1,
  "updatedAt": "2025-01-01T00:00:00.000Z",
  "entries": [
    {
      "id": "entropy",
      "name": "熵",
      "aliases": ["entropy", "信息熵"],
      "initial": "S",
      "tags": ["物理", "信息论"],
      "summary": "度量系统的不确定性或无秩序程度。",
      "content": "## 信息论定义\n\nH(X) = -Σ p(x) log₂ p(x)……",
      "createdAt": "2024-11-02T08:00:00.000Z",
      "updatedAt": "2024-12-20T15:10:00.000Z"
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `version` | 文档结构版本，当前为 `1` |
| `updatedAt` | 整份文档的最后写入时间（写路径自动维护，可留空） |
| `entries` | 词条数组 |

> 也可以直接写一个**裸数组**（`[{...}, {...}]`）作为 `entries`，加载器同样接受；但保存时总会写成上表的完整结构。

## 词条字段

| 字段 | 必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| `id` | ✅ | string | 稳定标识，用于分享链接（`#/?e=entropy`）。只允许字母、数字、`.`、`_`、`~`、`-`，且必须以字母或数字开头，最长 128。**改名不改 id**，这样旧链接不会失效 |
| `name` | ✅ | string | 词条名，**全集合内唯一**（忽略大小写）。最长 200 |
| `aliases` | ❌ | string[] | 别名，参与搜索与「精确匹配」。最多 50 个，每个最长 200 |
| `initial` | ❌ | string | 覆盖首字母分桶，取值 `A`–`Z` 或 `#`。留空则自动判断（中文取拼音首字母） |
| `tags` | ❌ | string[] | 标签，可用 `tag:标签` 精确筛选。最多 50 个，每个最长 64 |
| `summary` | ❌ | string | 一句话简介，显示在列表里。最长 500 |
| `content` | ❌ | string | 正文，Markdown 子集（见下）。最长 200000 |
| `createdAt` | ❌ | string | ISO-8601 时间；由写路径自动填写 |
| `updatedAt` | ❌ | string | ISO-8601 时间；每次保存自动刷新 |

未知字段会被忽略（不会报错，也不会写入），空字符串与空数组在保存时会被省略，因此文件保持干净、diff 稳定。

## 校验规则

加载时是**宽容**的：单个坏词条会被跳过并在「设置 → 当前状态」里报告，不会让整页空白。
写入时是**严格**的：任何一条不合规都会整体拒绝（后端返回 `422`，网页在编辑器里高亮字段）。

会被拒绝的情况：

- 缺 `name`；`name` 与已有词条重名；`id` 重复或格式非法；
- 别名与另一个词条的名称完全相同（会提示 `shadowed`，「别名 X 与已有词条名称重复」）；
- 字段超长或数组超量；
- `initial` 不是单个 `A`–`Z`/`#`。

## 正文可用语法（Markdown 子集）

| 语法 | 效果 |
| --- | --- |
| `# 标题` … `###### 标题` | 渲染为 `h2`–`h6`（`h1` 留给词条名） |
| 空行分段，单换行 | 段落 / `<br>` |
| `- 项`、`1. 项`、缩进两级 | 无序/有序列表、嵌套 |
| ```` ```js ... ``` ```` | 代码块（内容不参与格式化） |
| `> 引用` | 引用块 |
| `\| a \| b \|` + `\| --- \| --- \|` | 表格（`---:` 右对齐、`:--:` 居中） |
| `---` | 分隔线 |
| `` `代码` ``、`**粗体**`、`*斜体*`、`~~删除线~~` | 行内样式 |
| `[文字](https://…)`、`![图](https://…)` | 链接与图片（仅允许 `http`/`https`/`mailto`/相对地址） |
| `[[熵]]`、`[[熵\|熵与信息]]` | 跳转到另一个词条；目标不存在时显示为灰色文字 |
| 裸 URL | 自动成为链接 |

不支持（有意为之）：原始 HTML、脚注、引用式链接。原始 HTML 会被转义成文字显示 —— 这样任何人的词条都无法在读者浏览器里执行脚本。

## 中文首字母是怎么来的

`web/js/core/pinyin-table.js` 是一张「码点 → 拼音首字母」的紧凑查表（覆盖 GBK 的 20892 个汉字，约 30 KB，gzip 后约 14 KB），由 `tools/gen_pinyin_table.py` 从 [pypinyin](https://github.com/mozillazg/python-pinyin) 生成：

```bash
python3 -m venv .tools/venv
./.tools/venv/bin/pip install pypinyin==0.55.0
./.tools/venv/bin/python tools/gen_pinyin_table.py
```

规则：先跳过空白、标点、符号（`《存在与时间》` → `C`），拉丁字母取首字母（`Émile` → `E`、`Ｇraph` → `G`），数字与无法识别的字符进入 `#` 桶。

**多音字限制**：逐字查表没有词语上下文，例如「重庆」会取 `重` 的默认读音 `zhòng` → `Z`。要修正就给该词条加 `"initial": "C"`。

## 手工编辑建议

- 用两个空格缩进（仓库里有 `.editorconfig`），保持 diff 干净；
- 提交前跑一次 `npm test`：`tests/data-files.test.js` 会校验整份文件可解析、无重复 id、每个词条都有合法首字母；
- 网页上「导出 JSON」得到的文件就是这个格式，可以直接覆盖回仓库。
