# 词条格式与维护

全部词条在一个文件里：`web/data/entries.json`。改完提交推送即生效。

## 文件结构

```json
{
  "version": 1,
  "entries": [
    {
      "id": "complexNumber",
      "name": "Complex Number",
      "nameZh": "复数",
      "aliases": ["complex number"],
      "aliasesZh": ["虚数"],
      "tags": ["Math"],
      "tagsZh": ["数学"],
      "summary": "An ordered pair (a, b), written as a + bi.",
      "summaryZh": "写成 a + bi 的有序对 (a, b)。",
      "content": "- **Complex number**: an ordered pair $(a, b)$ …",
      "contentZh": "- **复数**：有序对 $(a, b)$ …",
      "createdAt": "2026-10-04",
      "updatedAt": "2026-10-04"
    }
  ]
}
```

`version` 是文档结构版本，`entries` 是词条数组（也可以直接写一个数组）。

## 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | ✅ | 稳定标识，决定分享链接 `#/e/complexNumber`。只用字母、数字、`.`、`_`、`~`、`-`，以字母或数字开头，最长 128。**改名不要改 id** |
| `name` | ✅ | 英文名称（基准语言），全集合内唯一（忽略大小写），最长 200 |
| `nameZh` | | 中文名称，最长 200 |
| `aliases` / `aliasesZh` | | 别名，参与搜索与精确匹配；最多 50 个，每个最长 200 |
| `tags` / `tagsZh` | | 标签，可用 `tag:标签` 筛选；最多 50 个，每个最长 64 |
| `summary` / `summaryZh` | | 一句话简介，显示在标题下方，也参与搜索；最长 500 |
| `content` / `contentZh` | | 正文，Markdown 子集（见下）；最长 200000 |
| `initial` / `initialZh` | | 覆盖首字母分桶，取值 `A`–`Z` 或 `#`；留空自动判断 |
| `createdAt` / `updatedAt` | | 日期，见下 |

英文是基准语言，`…Zh` 字段全部可选。未知字段会被忽略，空值与空数组会被跳过。

## 双语

- 界面默认英文，页头可切到中文；切换后整页跟着变，选择按设备记住。
- **按字段回退**：缺哪个中文字段就显示英文的那一个（可以只翻正文、名字留英文）。
- **一次只显示一种语言**：中文界面不会附带英文名，反之亦然。
- 搜索同时匹配中英字段，所以英文界面下搜「复数」也能找到 `Complex Number`。
- `[[熵]]` 和 `[[Entropy]]` 指向同一条词条。
- 默认语言在 `web/config.json` 的 `site.defaultLocale` 里改。

## 日期

只写日期即可：`"2026-10-04"`；也接受完整 ISO-8601（`"2026-10-04T11:28:00.000Z"`）。
页面原样显示只到日的写法，不做时区换算。

页脚的「更新于」自动取所有词条里最新的日期，不需要维护文件开头的任何字段。

## 正文语法

Markdown 子集：

| 写法 | 效果 |
| --- | --- |
| `# 标题` … `###### 标题` | 标题（渲染为 h2–h6） |
| 空行分段，单换行 | 段落 / 换行 |
| `- 项`、`1. 项`、缩进两级 | 列表、嵌套 |
| ```` ```js … ``` ```` | 代码块 |
| `> 引用`、`---` | 引用、分隔线 |
| `\| a \| b \|` + `\| --- \| --- \|` | 表格 |
| `` `代码` ``、`**粗体**`、`*斜体*`、`~~删除线~~` | 行内样式 |
| `[文字](https://…)`、`![图](https://…)` | 链接、图片（只允许 http/https/mailto/相对地址） |
| `[[词条名]]`、`[[词条名\|显示文字]]` | 跳转到另一个词条 |
| 裸 URL | 自动成为链接 |

公式（KaTeX）：

| 写法 | 效果 |
| --- | --- |
| `$a + bi$`、`\(a + bi\)` | 行内公式 |
| `$$…$$`、`\[…\]` | 独立成行的公式 |

公式里可以放心用 `_`、`^`、`*`、`{}`、`\`；代码块和行内代码里的 `$` 不会被当成公式；
`$5 和 $6` 这类货币写法不会被误判。写错的公式会渲染成红色错误提示，不会让页面出错。
原始 HTML 会被转义成文字显示。

## 维护流程

```bash
# 1. 改词条
$EDITOR web/data/entries.json
# 2. 自检（JSON 语法、字段合法性、重名、id、时间、搜索可用性、页面引用）
npm test
# 3. 提交
git commit -am "content(entries): add 复数"
git push
```

常见改动：

| 想做的事 | 怎么做 |
| --- | --- |
| 加一条 | 往 `entries` 里加一个对象，`id` 与 `name` 必填 |
| 改显示名 | 改 `name`（或 `nameZh`），**保留 `id`**，旧链接继续有效 |
| 只翻正文 | 加 `contentZh`，名字留英文 |
| 删除 | 删掉整个对象（注意别留下多余逗号）；指向它的 `[[链接]]` 会自动变成灰色文字 |
| 合并两条 | 内容并进保留的那条，把另一条的名字加进 `aliases` |
